🎯 책임 (Single Responsibility)
예약 1건의 정체성을 단일 행으로 표현. 누구의(booker_*) / 어디서(channel) / 무엇을(agency)이라는 식별 정보만 보유. 금액·결제·정산·여행자·행사 세부는 모두 별도 테이블에 위임.

왜 이렇게 설계됐나

  • 결제주체가 둘이어도 원장 자체는 하나 → 예약 정체성 보존
  • booker_* 스냅샷 — 회원정보 변경에 예약 기록이 흔들리지 않음
  • channel/agency는 식별자만. 결제·정산 분기는 ledger_items의 type 코드가 담당
  • 한 원장에 다중 여행사 매핑 금지 (당사자 모델 도메인 룰)

주변 테이블과의 관계

  • rsv_travels ← 1:N (행사 이동 이력)
  • rsv_channel_links ← 1:N (채널 주문번호 다중)
  • rsv_agency_links ← 1:N (행사이동 시 신규 발급)
  • rsv_travelers ← 1:N (개별 승객)
  • rsv_ledger_items ← 1:N (모든 금액 거래)

자주 받는 질문

예약자가 회원정보(이름/연락처)를 바꾸면 원장에도 반영되나요?
반영 안 됨. booker_*는 예약 시점 스냅샷. 회원 마스터(members)의 최신값은 booker_user_id로 join해서 별도 조회.
한 예약에 채널 2개(SSG + 트립스토어) 동시에 가능한가?
불가. rsv_ledgers.channel은 단일 값. 다른 채널 예약은 별개 원장. 결제주체 둘 → 한 원장 + ledger_items 다중 행으로 표현.
status 4단계 외에 환불·부분취소는 어떻게 표현되나?
status는 예약 전체의 큰 흐름만. 환불·부분취소·인원취소 등 세부 분기는 rsv_ledger_items에 시계열 행으로 추적.
비회원 예약 처리는?
booker_user_id=NULL 허용. booker_name/mobile/email은 입력값 보존.

  • 네이버쇼핑은 sync 아님 (PG 직결, 2026-06-09 정정)

📍 1. 신규 예약 (3명 패키지, 트립직판)
