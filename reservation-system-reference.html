📌 한 줄 요약: 예약관리에서 그동안 발생한 10대 문제가 신규 예약시스템 1차에서 모두 해결됩니다. 예약병합·결제이관 2건만 이번 제외 확정.

✅ 해결됨 DONE · 10

예약관리에서 겪었던 핵심 문제들이 신규 예약시스템 1차 작업으로 모두 해결

① 한 예약 건에 여러 결제주체 등록 가능 DONE
예약자가 일부 금액은 트립결제, 나머지는 여행사결제로 처리한 경우 한 건의 예약을 두 개로 나눠서 정산하던 문제 해결. 채널사·여행사·트립 결제 자유 조합 가능.
여행사 결제: 자동 데이터 생성 + 관리자 수정 가능
채널사 결제: 자동 데이터 생성 + 관리자 수정 X (PG 연동 보호 — 뒷단 수정 불가능)
조합: 한 예약 = 채널사 + 여행사 + 트립 동시 가능
② 행사이동 기능 DONE
취소·재예약 우회 없이 동일 여행사 다른 행사로 이동. 금액·특가·쿠폰 자동 재계산.
③ 결제링크 동시 다중 생성 + 연락처 직접 입력 발송 DONE
한 예약에 결제링크 N개 동시 유효 + 수신자별 휴대폰·금액 직접 입력 + 알림톡 발송. 1/N 균등분할 자동.
④ 결제수단 손쉬운 변경 DONE
예약금액 100→200→100 수동 조작 없이 재결제 링크로 변경. 사용자 "내 예약" 금액 일관 유지.
⑤ 쿠폰 금액 자동 조정 (방향1 비율차감) DONE
인원 차감/판매금액 변동 시 쿠폰 금액이 판매가 비율로 자동 일부 취소 처리. 운영자가 추가할인에 수동 입력하던 방식 제거.
예시: 3명 → 2명 (66.7%) → 쿠폰 20,000 × 66.7% = 13,340원
⑥ 취소위약금 결제→예약 시스템 이동 DONE
결제금액에서 따로 매기던 위약금을 예약 원장 800(ADJUSTMENT)으로 통합. 인원 삭제 후 자동 [+금액 추가] 모달.
⑦ 인원 추가·삭제 시 할인금액 자동 계산 DONE
운영자 수기 계산 제거. 인원별 100·202 자동 역분개 + 쿠폰 자동 비율 차감.
⑧ 예약관리 상세 — 원장 개념 / 통장 표시 DONE
"예약관리 금액·결제금액 히스토리 확인 어려움" 문제를 어드민 화면에서 원장 UI로 해결. 1차에 같이 진행.
스키마: rsv_ledgers / rsv_ledger_items / rsv_ledger_item_types 반영 + 어드민 원장탭 노출
관련 페이지: 상문님 원장 상세 정책 / 원장 시트
딥다이브 필요한 항목 (펼치기)
• 정산 관련 원장 항목 로직 (여행사별 다르게 지정될 가능성) — 정산정책 분기
• 정산기준금액 설정 — 어떤 원장 항목으로 설정하는 화면 기획 필요
• B / B-G / H / I 데이터베이스 매핑 (예약 보유 vs DB 정의)
⑨ 예약 건 단위 취소위약금 적용 처리 DONE
기존(인원별 취소위약금) + 추가(예약 단위 취소위약금) 두 가지 모두 관리 가능. 1차 ⑥ 취소위약금 시스템 변경 작업에 같이 포함.
⑩ 취소완료된 예약의 금액·인원 표시 기준 통일 DONE
어드민↔파트너스 인원 데이터 불일치 + 취소완료 예약의 금액 표시 정책 SSOT 확정. 5개 영역(어드민 목록/엑셀, 파트너스 목록/엑셀, 정산 엑셀) 통일.
제한사항: 최초 예약 인원에서 추가된 인원은 추적 가능 / 제외된 인원은 추적 불가

❌ 이번 제외 SKIP · 2

정책·범위 결정으로 신규 예약시스템 1차에서 제외 확정

예약 병합 기능 SKIP
동행자 따로 예약, 여행사 취합 요청 등 케이스. 파트너스에서 필요한 기능이라 이번 범위에서 제외.
제외 이유: 서비스 운영팀은 결제이동 기능이 필요하지 병합은 크게 필요로 하지 않음
대체 처리: 결제이관(현재 제외) 또는 행사이동으로 일부 케이스 흡수
참고 — 병합 시 필요했던 정책 (펼치기)
병합 가능 기준: 예약접수/예약완료/취소요청 상태 + 예약채널·여행사·출발일 동일
예약상태 우선순위: 예약완료 > 예약접수 > 취소요청
대표 예약 vs 새 예약 생성 두 방법 모두 허용 가능
결제이관 요청 기능 SKIP
채널사 예약(SSG/11번가 등) 결제-예약 매칭 오류 시 개발실 이관 요청 기능 — 완전 제외 결정 (2026-06-08).
대체 처리: 행사이동으로 일부 대체. 또는 별도 프로세스 신설 (정책 재검토 시)
