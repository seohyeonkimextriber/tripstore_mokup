📋 정리 필요 (진희·BE 협의)
  1. 다이나믹 응답 파싱 — TMG checkAvailability가 일별 요금 breakdown을 반환하는지 확인 (현재 요금 정책 v7에 "밤=1박씩"으로 명시되어 있어 저장은 되어 있을 것).
  2. 앵커 정책 default — 얼리 = 첫날 / 레이트 = 마지막날. 관리자가 변경 가능하게 할지, 시스템 고정으로 갈지 결정.
  3. 기존 % 데이터 마이그레이션 — 얼리/레이트 %는 그대로 사용 가능. 아동가만 절대금액으로 환산 후 저장 (스냅샷 시점 요금 × 기존%).
  4. 일별 요금 refresh 트리거 — dailyRates 갱신 시 얼리/레이트 실제 금액 자동 재계산 훅 추가 필요. STATIC 타입은 스킵 (요금 정책 v7 동일).
  5. 박수 변경 시 재계산 룰 — 3박권 → 4박권 개편 시 일별 요금 전량 재조회 + 아동가 재입력 필요. 얼리/레이트 %는 그대로 유지.
