매핑 규칙 (SystemLedgerItemType.kt 기준)

1) PG 결제 row 적재 → 4001 PAYMENT_PG 1건. 취소·환불은 4101 REFUND_PG (4xxx 자금 입출금).

2) PG 정산 row 적재 → 6010 + 7010 + 7020 + 7021 4-item을 settlement event 받아서 append. 공급가/부가세 분해는 reservations 원장이 아니라 settlement 도메인의 lineage 책임 (02-ledger-items.md SourceType과 SourceKey).

3) 채널 정산 row 적재 → 6000 + 7000. 채널결제 타입(11번가/SSG/THT/카카오쇼핑)이면 4001 PAYMENT_PG도 함께 (PaymentOwner.PLATFORM 경로지만 원장 자금주체는 PG).

4) 엑스트라이버 정산상세 → 예약 시점에 이미 적재된 2002/2202 (여행사 할인) + 정산 시점 6020 FEE_PLATFORM. "공제금액" 컬럼은 별도 ledger 코드 없음 → BE summary API의 도출값으로 노출.

5) 취소 시 기존 item 삭제 X. 5xxx CANCELLATION + 대응 reversal item 추가 (ADR-0006).

6) executedAt 으로 대기/실행 분리. 정산/결산/현금 잔액 리포트는 실행 item만 본다 (ADR-0009).
