④ 상문님 v2 정책 요약 (실무 정리)
  1. 정산기준금액에서 트립할인은 뺴지 않는다. 여행사 입장에서는 여행사 부담 할인만 뺀 값이 정산 base가 됨. 트립할인은 나중에 "공제금액"으로 여행사에게 되돌려주는 컨셉.
  2. 공제금액 = 서비스이용료 + 회사부담할인 (트립할인). 트립할인이 더 크면 공제금액이 양수가 되어 여행사에 더 지급됨.
  3. 정산금액 = 정산기준금액 + 공제금액 — 이 값이 여행사가 실제 받는 금액.
  4. 세금계산서금액 = max(0, 서비스이용료 - 회사비용). 회사가 매출보다 비용이 더 크면 세법상 0원 처리 (예약4).
  5. 위약금은 별도 수수료율 3.30% 적용 (일반 예약 8.80%와 별도).
  6. 지급 상태 5단계: 지급대기 → 지급요청 → 지급완료 · 지급이월 (사유 기재) · 지급실패 (1안 재요청 / 2안 이월처리)
  7. 지급실패 → 이월 전환은 운영자가 사유 확인 후 수동 처리. 자동 재요청 아님.
  8. 조정 ↔ 예약 관계는 N:M. 별도 매핑 테이블 필요 (base_payment 같은 연결정보).
  9. 취소 시 예약1-1 자동 생성 — 원본 예약과 반대부호로 지급원장에 append.
