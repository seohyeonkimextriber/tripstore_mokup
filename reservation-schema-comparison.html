이전 (ts_*) — 현행 트립스토어 예약 구조 신규 (rsv_*) — Ledger 기반 예약 구조 예시·추정 데이터 — 실제 운영 데이터와 다를 수 있음

✨ 한 줄 요약

현행 ts_*는 예약 1건이 여러 행(row)에 흩어진 평면 구조이고, 결제주체가 둘이면 예약 자체를 2개로 쪼개야 했음. 신규 rsv_*는 예약 1건 = 원장(ledger) 1개이며, 모든 금액·결제·정산이 rsv_ledger_items의 시계열 다중 행으로 저장됨 → 한 예약 안에 채널·여행사·플랫폼 결제가 공존 가능.

1. 핵심 차이 4가지

관점 이전 (ts_*) AS-IS 신규 (rsv_*) TO-BE
마스터 단위 ts_reservation + ts_reservation_order (예약/주문 분리) rsv_ledgers 단일 원장
금액 흐름 ts_reservation_order의 컬럼들에 압축. 변동 이력 없음 rsv_ledger_items 다중 행. 시계열 원장 기록
다중 결제주체 한 예약에 표현 불가 → 예약 2건으로 쪼개서 운영 한 원장 안에 채널/여행사/플랫폼 결제 공존
항목 분류 하드코딩 컬럼 (status, type 등) rsv_ledger_item_types enum 정규화 (100~900, 9범주 39항목)
Audit 일부 테이블만 _aud 거의 모든 핵심 테이블 _aud 일관 (Envers)

4. 양쪽 구조 시각 비교 (같은 예약, 다른 모양)

이전 (ts_*) — 행 1개 안에 모든 금액 압축

SELECT reservation_code, product_price,
       discount_amount, coupon_amount,
       payment_amount, payment_status
FROM ts_reservation_order
WHERE reservation_code = '26042623-1700101V';

-- 결과: 1행
-- 금액 변동 이력? 없음
-- 인원별 금액? 컬럼에 없음
-- 분할결제 2건? 별도 PG 테이블에서 join

신규 (rsv_*) — 시계열 행으로 모든 흐름 추적

SELECT li.type, li.passenger_id, li.amount,
       li.created_at, li.memo
FROM rsv_ledger_items li
JOIN rsv_ledgers l ON l.id = li.ledger_id
WHERE l.code = '26042623-1700101V'
ORDER BY li.created_at;

-- 결과: 12행 (시계열)
-- 100·202·301·401·500·601·602 모두 보임
-- 분할결제 = 401 행 2개로 표현
