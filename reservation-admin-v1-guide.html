가능한 액션 2026-06-11 미팅: 기본가만 자동

인원 추가 연령구분 + 인원수를 여러 행 한 번에 등록. 원장에 인원별 1000(상품정가) 자동 생성. 특가/할인은 기본가만 적용 (할인 분담 정보가 모호한 경우 담당자가 별도 항목 수동 입력).
📌 미팅 결정: 기존 예약자 = 특가가 적용된 상태인데, 추가 인원에 대해 같은 특가 분담 정보(채널/플랫폼/여행사)를 자동 결정하기 어려움. 운영자가 명시적으로 입력하는 게 안전.
인원 삭제 체크박스로 선택 후 삭제. 역분개 자동 + [+금액 추가] 모달 자동 표시
안내: "인원 취소에 따라서 발생하는 취소위약금이 있는 경우 금액을 입력해주세요" → 위약금 없으면 모달 닫기
인원별 보기 토글 예약자·동행별 원장 항목 분리 표시

운영 시나리오

1. "성인 1명 추가" — 친구 함께 가요
[인원 추가] → 성인 1행 등록 → 1인 상품가 699,000 자동 입력 → 특가 −13,000 분담 정보는 담당자 수동 입력 → 결제필요금액 +686,000 추가
2. "동행자 1명 못 가요" — 위약금 청구 (3명 → 2명)
동행자 체크박스 선택 → [인원 삭제] → 해당 인원 100·202 자동 역분개 → 자동 [+금액 추가] 모달 → 취소위약금(7010) 입력
3. "3명 다 못 가요" — 전원 삭제
전 인원 체크 + [인원 삭제] → 예약 전체 취소 흐름으로 자연 전환 (별도 차단 없음)
💡 여행자와 예약자는 따로 관리. 예약자(booker)는 회원·연락처 정보, 여행자(travelers)는 실제 탑승 인원으로 별도 테이블.
인원(여행자) 삭제는 예약자 지정과 무관하며, 전원 삭제 시 예약 전체 취소 흐름으로 자연 전환 (별도 차단 없음).
📌 향후 개선 사항: 전원 삭제 시 자동으로 결제 취소 + 예약 전체 취소 처리 프로세스 자동화 (현재는 수동 흐름)
🔍 신규 인원 타입 추가 검토 중 (2026-06-11 미팅):
예: 성인 2명 + 유아 1명 예약 → 큰 아이가 아동으로 추가되는 케이스. 아동 가격 정보 / 특가 분담 정보를 시스템이 알 수 없는 상황.
• Option A: 그냥 성인으로 추가하고 금액 차감으로 처리 (분담 정보 = 여행사로 자동)
• Option B: 신규 타입 추가 자체를 차단, 운영팀이 별도 CS 채널로 처리
→ 상문님이 특가 정보 저장 구조 분석 후 정책 결정 예정. 1차 오픈 시점에는 신규 타입 추가 비활성화 가능성.

① [인원 삭제] → [+금액 추가] 모달 자동 표시 → 모달 닫기 (위약금 없음)
💡 핵심 변화:
• 취소위약금 관리 주체 이전: 기존 결제 시스템 → 예약 원장(7010)으로 완전 이전
• 결제 서비스는 "결제·환불" 트랜잭션만 관리, 위약금은 예약 원장의 책임
• 결제 후 위약금 발생 시 결제 자체는 깨지지 않고 원장에서 처리 → 회계 정합성 개선
📌 미팅 결정 (1:29~1:34 "취소위약금 예약원장 우선 오픈" 단락): 1차 오픈에 포함. 인원 삭제 시 [+금액 추가] 모달 자동 표시 → 위약금(7010) 입력 흐름으로 ① 인원 관리·② 예약 금액 관리 안에 이미 반영됨.

⑤정산 시스템 연계

변경된 예약 원장 기준으로 정산 데이터 인터페이스 개선. 신규 API 설계 (기존 API 재활용 X)

정산 데이터 개선 흐름 (1차 오픈 함께)

1단계 (9월 1차 오픈)
변경된 예약 원장 데이터 구조 기준으로 정산 시스템이 받아갈 신규 API 스펙 정의 (기존 API 재활용 X)
2단계 (9월 1차 오픈)
현정님이 회계 인식 기준으로 원장 항목 그룹핑 가이드 작성 → 정근님이 가이드 기반 API 스펙 작성
3단계 (9월 1차 오픈)
정산 시스템이 신규 예약 원장에서 받은 데이터로 정상 계산 → 기존 정산 로직과 호환
4단계 (후속)
정산 결과 (지급/PG 수수료/채널사 수수료) → 예약 원장으로 역반영 → 최종 0원 결산 모델 지향
💡 정산 API 신규 스펙 (현정님 + 정근님 협의 필요):
• 기존 정산 API를 그대로 신규 원장에서 내려주는 식은 NO
• 신규 원장 항목 분류를 그대로/집계해서 정산이 받아가는 신규 스펙이 정답
• 현정님이 "원장 각 항목을 회계학적으로 어떻게 인식할지" 정리 → 정근님이 가이드 기반 API 사이즈 산정
• 6월 중 정리, 7월 리뷰 목표
📌 노션 트래커 항목명 정정: 기존 "신규 정산 시스템" → "포트원 PG 정산 시스템 연동 개선" 으로 정정. 정산 시스템은 이미 운영 중이며, 신규 원장 기반으로 데이터 인터페이스만 개선하는 작업.
