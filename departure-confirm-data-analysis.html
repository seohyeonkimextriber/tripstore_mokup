📊 데이터가 말해주는 6가지

  1. A 중 자동 매핑 가능 = 73.7% (369 / 501) — 출발대기 진입 후보(A)의 4분의 3이 시스템 자동 처리 가능. 운영자 수동 부담 26%로 축소.
  2. B(모객 인원 충족)이 압도적 핵심 동인 — A 대비 71.3% — booked_seats ≥ threshold_for_departure가 단일 변수로 가장 강력. PACKAGE 상품의 자동화 동력.
  3. 메이저 3사 자동화 가능 — 하나투어 86.8% / 노랑풍선 78.7% / 모두투어 63.0%. ts_reservation_order.package_code 경유 매칭 후 99% 조인 성공.
  4. C(시그널)은 온라인투어 단독 9건 — A∩C가 적지만 보조 시그널로 가치 있음. E-Ticket 발송완료가 진짜 출발확정 신호.
  5. AIRTEL은 100% 자동 매핑 — 인원 무관(2인 이상이면 출발) 룰이라 A∩AIRTEL=59건은 별도 조건 없이 자동 처리 가능. 에어텔닷컴 케이스 자동화율 100%.
  6. 나머지 26.3%(132건)는 운영자 수동 영역 — 주로 PACKAGE 중 모객 미달 + 시그널 없는 케이스. D-7 알림 + 운영자 [출발확정 처리] 액션 룰 필요.
Recommended Rules

출발확정 자동 매핑 룰 (제안)

상품 유형 + OR 합집합 기반.

1차 룰

AIRTEL · 결제완료

에어텔/자유여행 = 인원 제약 없음. 결제완료 = 출발확정 자동 처리.

  • kind = AIRTEL
  • AND status = 결제완료
  • → 자동 출발확정 (즉시)
2차 룰 (핵심)

PACKAGE · 모객 충족

패키지 = 최소 모객 인원 도달 시 출발확정. 가장 많은 케이스 커버.

  • kind = PACKAGE
  • AND booked_seats ≥ threshold_for_departure
  • → 자동 출발확정 (시스템 판단)
3차 룰 (보조)

여행사 시그널 신뢰

여행사가 명시적 출발확정 신호 보내는 경우 즉시 반영.

  • raw_status IN (E-Ticket 발송완료, 발권완료, 비자발송완료, 출발확정)
  • → 자동 출발확정 (시그널 즉시)
💡 운영자 수동 처리는 예외 영역만 — 위 3개 룰로 60% 커버. 나머지 40%(주로 결제 진행 중·취소·접수 단계)는 자연 진행 또는 운영자 액션 영역.
