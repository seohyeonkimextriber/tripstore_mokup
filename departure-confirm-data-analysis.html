Key Insights

핵심 인사이트 (정량 데이터 기반)

메이저 3사(하나투어/모두투어/노랑풍선)는 trips 패키지 잔여좌석 정보와 출발확정 시그널 모두 비어 있어 자동 매핑 불가

📊 데이터가 말해주는 6가지

  1. 3변수 동시 충족 = 0건 — 자동 출발확정의 "가장 안전한 영역"은 5월 데이터에 존재하지 않음. 변수 단일/조합 운영 필수.
  2. 온라인투어(여기어때)가 거의 모든 자동화 후보를 보유 — 출발확정 시그널 31건 100%가 온라인투어. A∩C 9건도 전부 여기.
  3. 참좋은여행은 잔여좌석만 매칭됨 — A∩B 11건 자동 매핑 가능. 다만 출발확정 시그널은 없음 (참좋은여행 raw status는 숫자만 0~9).
  4. 메이저 3사 잔여좌석 매칭률 0% — 하나투어 437건·모두투어 413건·노랑풍선 347건 모두 ts_packages.remaining_seats 정보 비어 있음. 패키지 인벤토리 연동 정책 차이로 추정.
  5. 인터파크/NOL 데이터 부재 — 노션 매핑 문서에 명시된 인터파크 `출발확정` 시그널은 5월 예약에 없음. 트립스토어 풀에 해당 여행사 상품이 없는 것으로 보임.
  6. 5월 예약의 73%는 이미 종결 — 출발완료 540건 + 취소 912건 = 1,452건. 신규 [출발확정] 도입은 미래 예약에만 의미 있음.

1차 시범 운영

온라인투어 단독 자동 매핑

출발확정 시그널이 명확하고 잔여좌석 정보까지 매칭되는 유일한 여행사.

  • A ∩ C 룰 적용: 예약완료 + `E-Ticket 발송완료` → 자동 출발확정
  • 월 기대 자동 매핑 = ~9건 (5월 기준)
  • 2차로 A ∩ B (잔여좌석 0) 추가하면 ~16건까지 확대
  • 여기어때 연동 채널 신뢰도 검증
전체 운영

나머지 여행사 = 운영자 수동 처리

메이저 3사 포함 대부분 자동 매핑 불가. 수동 액션이 표준이 되어야 함.

  • 운영자가 [출발확정 처리] 버튼 클릭 = lock
  • 참좋은여행은 잔여좌석 정보만 추가 활용 가능 (보조 시그널)
  • 메이저 3사에 출발확정 시그널 연동 추가 협의 필요 (장기)
  • 모객 미달 알림은 잔여좌석 매칭되는 여행사부터 시범
Methodology

사용 쿼리 (참고)

분석에 사용된 BigQuery 쿼리. 재현 가능합니다.

WITH base AS ( SELECT r.code, r.status_on_management, d.travel_agency_name, JSON_EXTRACT_SCALAR(d.raw_data, "$.status") AS raw_status, JSON_EXTRACT_SCALAR(d.raw_data, "$.eventCode") AS event_code FROM `tripstore-352708.svc_reservations.ts_member_reservation` r JOIN `tripstore-352708.svc_reservations.ts_agency_reservation_detail` d ON r.agency_reservation_detail_id = d.id WHERE DATE(r.reserved_at) BETWEEN "2026-05-01" AND "2026-05-31" ), with_pkg AS ( SELECT b.*, p.remaining_seats, p.kind FROM base b LEFT JOIN `tripstore-352708.svc_inventory.ts_packages` p ON b.event_code = p.package_code -- 행사 단위 조인 ) SELECT COUNT(*) AS total, COUNTIF(status_on_management="RESERVATION_CONFIRMATION") AS A, COUNTIF(remaining_seats=0) AS B, COUNTIF(raw_status IN ("E-Ticket 발송완료","발권완료","비자발송완료","출발확정")) AS C, -- A ∩ B ∩ C 등 ... FROM with_pkg
