Key Insights

핵심 인사이트 (v2)

자동 매핑 가능 영역 = 60.1% / 메이저 3사 모두 활용 가능 / B(모객 충족)가 압도적 핵심 동인

📊 데이터가 말해주는 6가지

  1. A ∪ B ∪ C = 60.1% (1,198 / 1,992) — 자동 출발확정 가능 영역이 절반 이상. 운영자 수동 부담 대폭 경감.
  2. B (모객 인원 충족)이 가장 큰 동인 — 52.6% — booked_seats ≥ threshold_for_departure가 단일 변수로 가장 강력. 메이저 3사도 모두 활용 가능.
  3. 메이저 3사 자동화 가능 — 하나투어 63.4% / 모두투어 54.9% / 노랑풍선 64.3%. v1 분석 결론("자동화 불가")은 매칭 키 오류였음.
  4. 온라인투어(여기어때)만 C 시그널 보유 — 31건 — E-Ticket 발송완료가 진짜 출발확정 시그널 역할. 다만 A∪B만으로도 메이저 3사 커버 가능.
  5. AIRTEL 9.8% / PACKAGE 89.8% — AIRTEL은 인원 무관(2인 이상이면 출발 가능)이라 결제완료=출발확정으로 자동 매핑 가능. PACKAGE는 threshold 기준.
  6. 예약완료(A) 단독으로는 약함 — 25.2% — A∩B 같은 조합이 더 강력. 하지만 OR 관계로 B 단독으로도 자동화 가능.
Recommended Rules

출발확정 자동 매핑 룰 (제안)

상품 유형 + OR 합집합 기반.

1차 룰

AIRTEL · 결제완료

에어텔/자유여행 = 인원 제약 없음. 결제완료 = 출발확정 자동 처리.

  • kind = AIRTEL
  • AND status = 결제완료
  • → 자동 출발확정 (즉시)
2차 룰 (핵심)

PACKAGE · 모객 충족

패키지 = 최소 모객 인원 도달 시 출발확정. 가장 많은 케이스 커버.

  • kind = PACKAGE
  • AND booked_seats ≥ threshold_for_departure
  • → 자동 출발확정 (시스템 판단)
3차 룰 (보조)

여행사 시그널 신뢰

여행사가 명시적 출발확정 신호 보내는 경우 즉시 반영.

  • raw_status IN (E-Ticket 발송완료, 발권완료, 비자발송완료, 출발확정)
  • → 자동 출발확정 (시그널 즉시)
💡 운영자 수동 처리는 예외 영역만 — 위 3개 룰로 60% 커버. 나머지 40%(주로 결제 진행 중·취소·접수 단계)는 자연 진행 또는 운영자 액션 영역.
