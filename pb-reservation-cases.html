4 케이스 비교 — 2026-05-29 회의 반영
PB 상품은 항공/숙박 각각 인디비(API 연동) 또는 수동으로 등록되어 총 4개 조합이 발생합니다.
조합별로 어드민 예약 처리 흐름이 달라지며, 한 건이라도 수동이 섞이면 예약 접수 단계에서 정지 후 어드민이 가능 여부를 확인한 뒤 고객 컨택을 거쳐 확정합니다.
📌 2026-05-29 회의 결정 사항
  • 인디비×인디비만 자동 컨펌(즉시 확정관). 가격 변동은 환율 수준 자동 허용 / 재고만 체크
  • 수동이 1건이라도 포함되면 → 예약은 결제까지만 받고, 공급사 예약은 호출하지 않음(접수 정지)
  • 23:30~00:00 홀드 프로세스는 폐기 → 즉시 확정관 PDP에 "페널티 발생 가능" 안내 문구로 대체
  • 수동 처리 완료 후 어드민이 인디비 측을 다시 조회 → 가능 확인 → 고객 컨택 → 확정
  • 재조회 시 가격이 달라져 있을 수 있음 → 차액 안내 후 고객 동의 필요 (동의 시 차액 결제, 거절 시 취소)
  • 탑승객 정보는 항상 어드민에 노출 (현재는 항공권 아래에서만 보임) — 보관/저장 정책은 별도 검토
  • 결제: PB 전체 전액 결제만, 취소는 모든 케이스 관리자 개입 필수
  • 모든 기능 어드민에 일원화 (파트너스 별도 분기 X, 권한으로 제어)
