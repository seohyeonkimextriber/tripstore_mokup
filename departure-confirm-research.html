패키지여행 업계가 사용하는 출발확정/모객/잔여좌석 라벨과 운영 룰을 정리. 트립스토어 정책 결정 시 참고하세요.

Industry Insight · 가장 중요한 발견

업계가 안고 있는 "출발확정" 신뢰 이슈

정책 결정 전에 반드시 알아야 할 도메인 컨텍스트.

🚨 업계 공통 문제
한국 패키지 여행 업계는 "출발확정 후 모객 미달로 취소" 이슈가 만성적입니다. 소비자가 [출발확정] 표시를 보고 연차까지 냈는데 일방 취소되는 사례가 많아 "출발확정"이라는 라벨의 신뢰가 약화된 상태입니다. 일부 여행사는 "허수 모객" (예약 인원 부풀리기) 관행도 있다고 보도됨.
📋 최소 모객 인원
15~30명
전통 패키지 일반 기준. 상품마다 다름. 최근 "1명만 모여도 출발" 같은 단독 출발 상품도 등장.
⚠️ 출발확정 → 취소
발생 빈도 ↑

Part 2 · UI Pattern by Screen

화면별 표시 패턴 (일반)

상품 목록부터 마이페이지까지, 각 화면에서 출발확정/모객을 어떻게 다루는지.

화면 핵심 표시 일반 패턴
📦 상품 목록 출발확정 / 모객완료 / 마감임박 카드 좌상단 배지 (1~3개 중첩). 모객완료는 카드 전체 흐림 처리 + "예약불가" 표시. 정렬: 출발확정 우선 → 모집중 → 모객완료
📅 출발일 캘린더 날짜별 모객 상태 날짜 셀에 색깔 dot (초록=확정/노랑=모집중/회색=불가). 클릭 시 "현재 N명 / 최소 M명" 모달 또는 툴팁
📄 상품 상세 잔여좌석 / 출발확정 여부 / 모객 인원 진행 예약 버튼 위에 "잔여 N석" + 출발확정 배지. 일부는 "현재 12명 예약 (최소 15명)" 진행 표시
💳 예약 직전 최종 확인 "본 상품은 최소 N명 모객 시 출발합니다" 약관 동의 체크 필수
👤 마이페이지 (고객) 예약 상태 단계 (Timeline) "예약접수 → 예약완료 → 출발확정 → 출발완료" 같은 3~4단계 timeline. 진행된 단계만 활성화.
🛠️ 운영자 화면 모객률 + 액션 버튼 행사별 모객률 %, 최소 인원 도달 시 알림 → 운영자 [출발확정 처리] 액션 버튼. 미달 시 [폐쇄/병합] 메뉴

⚠️ 핵심 운영 룰 — 출발확정 이후 잔여좌석을 숨기는 것이 일반적. 출발확정 후에도 취소가 발생할 수 있지만, 그 변동은 운영자 내부에서만 보이고 고객 화면엔 노출하지 않음 (신뢰 유지).
⚠️ 예외 흐름 — 출발확정 후 취소
취소가 발생해서 모객이 마지노선 이하로 떨어지면 → 운영자가 [모객 미달 처리] → 전체 예약 강제 취소 + 보상 약관 적용. 업계 일반적으로 이 시점이 출발 D-7 ~ D-3 정도. 그 이후는 취소가 발생해도 출발은 진행.
Part 4 · Recommendation

트립스토어 정책 권장

위 인사이트를 반영한 출발확정 운영 룰 제안.

💡 트립스토어 출발확정 룰 제안

  1. "출발확정" 라벨은 운영자 액션 기반 — 자동이 아닌 운영자 [출발확정 처리] 클릭 시점. 신뢰 보장 측면.
  2. 출발확정 후 잔여좌석 표시 OFF — 고객 화면엔 숨김, 운영자 내부만 표시.
  3. 출발확정 → 취소 일방 처리 금지 — 모객 마지노선 이하로 떨어져도 출발 진행 (보상 비용 < 신뢰 비용).
  4. 상품 유형별 자동/수동 분기 — 에어텔/FIT은 결제완료 시 자동 출발확정, 패키지는 운영자 수동 확정.
  5. "단독출발 보장" 마케팅 활용 — 신뢰가 약한 업계에서 차별화 포인트로.
  6. D-7 시점 자동 알림 — 모객 미달 행사 운영자 알림 (폐쇄/병합/단독출발 결정 유도).
