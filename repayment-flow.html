이 목업이 검증하는 정책 초안
  • 4단계 명시 프로세스: (1) 취소예정 마킹 → (2) 결제 URL 발송 → (3) 고객 결제 완료 → (4) 기존 결제 취소 API 호출
  • 결제 검증 룰 = SUM(활성) − SUM(취소예정) + SUM(신규) ≤ 예약관리금액
  • 재결제 대상은 관리자가 명시적으로 지정 (여러 건 조합 가능, 부분취소는 지원 결제수단만)
  • Step 2 완료 후 결제 URL 유효기간 24시간 · 만료 시 취소예정 자동 롤백
  • Step 3 실패 → 취소예정 자동 롤백 · Step 4 실패 → 취소실패 상태 + Slack 알림 (수동 대응)
  • 이미 취소예정인 결제는 재차 재결제 대상 지정 불가
