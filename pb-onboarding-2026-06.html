DAY 1 PB 사업 구조 & 소싱

6/18 (목) 10:00–11:00 · 트립스토어가 어떤 구조 위에서 PB를 운영하는지 큰 그림 잡기. 원본: 2026.04.07 PB 온보딩 킥오프

1. 시스템 구조

  • 트립스토어는 플랫폼이며, 별도로 TRP (Trip Partners) 시스템이 존재함.
  • 어드민과 파트너스는 서로 다른 개념이며, 현재 구조가 완전히 정리된 상태는 아님.
  • 파트너스는 랜드사·여행사가 상품 등록·예약 관리를 할 수 있도록 구축 중. 아직 개선이 많이 필요.
  • 현재는 어드민 + 파트너스를 함께 운영 중이라 초기에 다소 헷갈릴 수 있음.

2. 상품 등록·판매 구조

  • 파트너스에 등록된 상품은 트립스토어 플랫폼에 노출.
  • 트립스토어 자체도 하나의 여행사처럼 상품을 등록·판매.
  • 방향은 파트너스 중심이지만, 현재는 어드민 작업 비중이 큼.

3. PB 상품의 기본 구성

  • PB 상품 = 항공 + 숙소 + 투어/티켓 조합.
  • 현재는 에어텔 중심 운영, 투어·티켓 결합 패키지도 함께 판매 예정.
  • 가격 경쟁력 + 상품 매력도가 충분하면 에어텔/패키지 모두 운영 대상.

4. 소싱 구조

  • 항공: 일부 항공사 직접 연결 + 랜드사 공급.
  • 숙소·투어·티켓: 주로 베트남 현지 랜드사를 통해 소싱.
  • 현재 집중 지역: 푸꾸옥 · 나트랑 · 다낭 (베트남 중심).
  • 주요 협업사: TMG — JV(합작회사) 설립 추진 중.

5. TMG & 솔바이멜리아

  • TMG와 협업해 베트남 숙소 중심 상품 확대.
  • 솔 바이 멜리아 (Sol by Meliá) 상품은 2,000박 계약되어 있어 판매 확대가 중요한 목표.
  • 당분간 푸꾸옥 중심 다양화 → 이후 다른 지역으로 확장.
2026.06 업데이트 솔바이멜리아 푸꾸옥 — 가예약 + 출발확정 60건 프로모션 준비 중. 7월말~8월초 유류할증 인하 모멘텀 활용 예정.

6. 현재 운영 상황 (참고)

  • 4~5월 항공권 이슈로 일부 상품 판매 중단/축소 → 신규 세팅 다시 진행.
  • 우선순위: ① 솔바이멜리아 다양화 → ② 푸꾸옥 숙소 확대 → ③ 다낭·나트랑 확장.

7. 기대 역할

  1. 상품 운영 전반 — 기획·등록·예약 핸들링·전환 개선까지.
  2. 예약 취소 최소화 & 대안 제시 — 문제 발생 시 다른 숙소/항공/상품 전환 유도.
  3. 프로세스 개선 참여 — 자동 상품생성, 운영 화면 개선 논의에 운영자 입장에서 참여.

DAY 2 어드민 기본 세팅

6/19 (금) 13:00–14:00 · 환율·유류할증·공항이용료·여행보험·공급사·카탈로그·POST. 원본: 2026.04.08 어드민 기본 세팅

1. 환율 등록

환율 세팅 가이드는 슬랙 메시지 참고 (PB 운영방 핀 메시지).

2. 유류할증료

케이스처리
비엣젯요금표에 포함 (0원 설정)
이스타매달 말 정기점검 · 주로 항공사 공식 사이트에서 확인
누아항공 연동요금표에 포함 (0원 설정) · 단, 항공사·공항 기본 세팅 정보는 입력 필요

3. 공항 이용료

  • 출발 공항 + 도착 공항 각각 따로 등록 (왕복 기준).
    • 예) 인천 → 푸꾸옥: 인천공항 이용료 1개 + 푸꾸옥 공항 이용료 1개.
  • 공식 사이트에서 확인 · 매달 말 정기 점검 (변동 빈도 낮음).
  • 관리 대상 공항: 인천, 부산(김해), 나트랑, 푸꾸옥, 다낭.
  • 인천공항은 1터미널 vs 2터미널 이용료가 다를 수 있으니 항공사별 터미널 확인 후 적용.
  • 감면 대상은 패키지 특성상 적용 안 함.
실수 주의 인천공항 이용료를 2배로 입력하는 케이스 — 금지. (왕복이라도 인천 공항 이용료는 1번만)

4. 여행 보험

  • 별도 등록 없음 — 어시스트 카드만 사용.
  • 여행 일수(3·4·5·6박 등)에 따라 금액 다름.
  • 신규 기간(예: 5박 7일)이 생길 경우 새로 등록 필요.

5. 공급사 관리

  • 항공권 / 숙박권 / 투어·티켓 공급사 각각 등록.
  • 신규 공급사 발생 시 반드시 여기에 먼저 등록 → 이후 항공·숙박 등록 시 필드에 표시됨.

6. 카탈로그

유형예시 (푸꾸옥 상품 기준)

7. POST (포스트) 등록

  • 카탈로그 각 항목에 붙는 부가 정보 콘텐츠.
  • 종류: 소개, 핵심 포인트, 스페셜 혜택, 포함 사항, 불포함 사항, 유의사항, 안내 사항, FAQ, 환불 규정.
  • 등록 경로: 카탈로그 단위 직접 등록 OR PB 관리 > 포스트 관리 메뉴.
  • AI 자동 생성 기능 테스트 중 — 공급사 요금표 PDF 업로드 → 자동 파싱.
    • 취소/환불 규정 등 패키지 기준에 안 맞는 항목은 직접 수정.
  • 이미지는 포스트 > 소개 영역에서 등록.
  • 콘텐츠 소스: 랜드사/공급사에서 받은 자료 기반.
진행 중 포스트 등록 간편화 개발 작업 중 → 완료 후 기존 등록 건 재등록 필요할 수 있음.

8. 운영 알림 (매일 체크)

  • 요금 사용 기한 임박 알림 매일 확인 → 랜드사에 연장/신규 요금표 요청.
  • 랜드사·공급사 운영방 슬랙 초대는 영실 님 통해 처리.

DAY 3 상품 등록 & 가격·마진 관리

6/22 (월) 13:00–14:00 · 항공·숙박 등록 → 파트너스 상품 등록 → 가격 구조 → 3-Layer 마진 → 행사 가격. 원본: 2026.04.08 (항공·숙박 등록) + 2026.04.09 (상품·마진)

1. 항공권 등록

필드: 공급사, 좌석 클래스(이코노미 등), 블록/수의/소프트, 여행 기간, 요금 사용 기간, 출발·도착 공항, 항공사, 편명, 유료 할증료, 공항 이용료, 발권 수수료.

  • 수익률 = 무조건 0 (상품·행사 단위에서 마진 관리).
  • 운임 등록: 엑셀 업로드 OR 직접 추가.
  • 요금 사용 기한 만료 시 해당 항공권 연결 상품 전체 중단 → 기한 임박 알림 매일 확인 후 랜드사에 연장 요청.
  • 재고 소진 시 상태를 소진됨 / 예약 중단으로 변경.
  • 유아 항공 운임은 별도 문의 처리.

2. 숙박권 등록

필드: 공급사(TMG 등), 통화(동 VND → 환율 자동 환산), 요금 사용 기한, 숙소, 객실.

  • 객실 미등록 시 → 객실 추가 후 객실명·기준 인원 입력.
  • 수익률 = 무조건 0.
  • 아동가: 성인 공급가의 70% 기준 (50%는 역마진 위험).
  • 나이 기준: 플랫폼 기준 (만 12세 미만 아동, 만 2세 미만 유아).
  • 식사 타입(RO / BB / HB) 구분 입력.
  • 예약 인원 고정 기능 → OFF 유지.

3. 투어·티켓 등록

  • 카탈로그 기준: 스팟 체험.
  • 성인·아동·유아 공급가 + 소량 마진 반영.
  • 포스트(소개, 스페셜 혜택, 포함 사항 등) 랜드사 자료 기반 등록.
  • 이미지: ① 랜드사 요청 → ② 랜드사 사이트 캡쳐(동의 받고) → ③ 피그마 여행지 이미지 보드.

4. 상품 등록 (파트너스)

진입 경로
파트너스 > 상품 관리 > PB 상품 관리
핵심 팁
신규 등록보다 기존 상품 복제 강력 권장 (이미지 자동 컨포지)
구성 요소
상품 유형(에어텔/패키지) → 출발지·도착지 → 항공권 → 숙박권(숙소·객실) → 상품명·이미지·가격·여행자보험·얼리/레이트 체크인·취소 환불 조항

상품명

  • 추천 상품명 버튼 클릭 시 기본 포맷 자동 삽입.
  • 상품명 작성 가이드 노션 문서 별도 존재 — 등록 전 반드시 참고.
  • 서비스에서 실제 노출 확인 필수 (다른 상품과 비교해 눈에 띄는지).

상태설명

상품 일괄 동기화

  • 파트너스 수정 사항 → 실시간 업데이트.
  • 플랫폼 내부 시스템 수정이 필요한 경우(예: 태그 반영) → 상품 일괄 동기화 실행.

5. 가격 구조

항공권

항목설명
공급가운임 + 유류할증료(×2) + 공항 이용료 (+ 발권 수수료)
정가공급가 × (1 + 수익률)
판매가정가 × (1 − 할인율)

유류할증료·공항 이용료 미반영 원하면 운임 그대로 공급가. 수익률 = 0으로 설정.

숙박권

  • 공급가(VND 입력 → 환율 적용 자동 환산), 정가, 판매가 동일 구조.
  • 유아는 마진·할인 적용 제외 (공급가 = 정가 = 판매가).

6. 상품 마진 구조 (3-Layer)

성인 1인 원가 = 항공권 판매가(1인) + 숙소 판매가(1박) × 박수 ÷ 기준 인원 + 보험료 + 투어·티켓 판매가(해당 시) ↓ 3-Layer 연산 1. 원가 × (1 + 고정 마진율) = 기준 원가 2. 기준 원가 × (1 + 추가 마진율) = 판매가 (서비스 표시) 3. 판매가 × (1 + 정가 마진율) = 상품가 (취소선 표시) → 최종 표시가는 둘 다 천 단위 절삭
마진 종류역할현행 설정
고정 마진결제 수수료(3.3%) + 세금 커버 최소 보장 수익10~15%
추가 마진마케팅(인플루언서 등) 수수료, 채널사(예: 카카오뱅크) 수수료0% (액션 없을 때)
정가 마진특가 표시용 상품가 생성 (% or 금액)10%
예시 원가 100만원 → 고정 5% → 기준원가 105만원 → 추가 5% → 판매가 ~110.3만원 → 정가 12% → 상품가 ~123.3만원.

7. 행사별 가격 관리 (경쟁사 비교)

  1. 어드민 > 상품 관리 > 행사 조회.
  2. 숙소명 + 출발일 태그로 전체 여행사 상품 조회.
  3. 엑셀 다운로드 후 피벗으로 여행사별 평균·최소 판매가 확인.
  4. 우리 상품이 비싸면 마진 매가, 싸면 마진 방어 조정.
  5. 해당 행사 PB 행사 관리 화면에서 직접 마진 조정.

1. TMG 요금표 연동 & 카탈로그 매핑

  • 진입: PB 관리 > TMG 숙소 요금표 관리.
  • TMG 시스템에 등록된 요금표를 트립스토어 시스템에서 수신.
  • 카탈로그 매핑 작업 필수.
    • TMG 숙소 ID ↔ 트립스토어 카탈로그 ID 연결.
    • 예) TMG 솔바이멜리아 = ID 1 / 트립스토어 카탈로그 = 13번·15번.
    • 객실 단위도 동일하게 매핑 (트립스토어 객실 ID 기준).
  • 매핑 완료 후 확인하기 클릭.
  • PB 숙박권 생성 선택 → 요금 정보 자동 입력된 숙박권 등록 화면 표시.

2. 자동 상품 생성 시스템 방향

기본 로직

  • 항공(누아 API, 실시간 재고+요금) + 숙소(TMG API) 조합 → 상품 자동 생성.
  • 동일 스펙 다른 여행사 대비 가격 경쟁력 필터링 자동화.
    • 예) 동일 항공+숙소+스펙, 에어텔닷컴 80만 / 오대여행 90만 / 트립스토어 100만 → 미생성.
  • 경쟁사 상한선 안쪽에 들어오는 상품만 생성.

상품 조합 세트

세트구성
1세트항공 + 숙소 + 보험
2세트항공 + 숙소 + 투어·티켓 + 보험
3세트항공 + 숙소 + 숙소 옵션(식사/얼리체크인/픽업) + 투어·티켓 + 보험
  • 투어·티켓 조합 수(1/2/3개) 등 조합 조건 세팅은 PB 운영 담당자가 직접 설정.
  • 세팅 완료 후 백엔드에서 자동 생성 (API 조합 로직 담당).
  • 수동 등록 상품(가격 조정 필요) + 자동 생성 상품 병행 운영.

PB 운영 담당 업무 스코프

  • 생성된 상품 모니터링 & 관리.
  • 조합 조건 세팅 (어떤 세트를 만들지 설정).
  • 이상 상품 확인, 운영 현황 리포팅.
  • 수동 등록 상품 가격 조정.

3. 특이사항

다낭 프리미엄 패키지 (TMG 협의 중)

  • 하나투어처럼 저렴한 자유여행 말고 가격대 있는 프리미엄 상품 방향.
  • 트립스토어 여행객 중 프리미엄 대상 약 20~30%에서 수요 있음.
  • TMG와 코스트/호텔 정리 후 공유 예정.
인수인계 이 영역은 서율님 인수인계 자료를 별도 참고. (랜드사 컨택 포인트·요금표 관리 룰·이슈 히스토리 등)
