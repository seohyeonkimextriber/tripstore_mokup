결정 필요 사항

부서 협의 / 추가 결정 대기 2건

actionType 매핑 — 포트원 4종 → 우리 2종 갭

⏳ 협의 대기 경지실 + 개발실

포트원: APPROVAL / FULL_CANCEL / PARTIAL_CANCEL / UNCLASSIFIED_CANCEL 4종 · 우리: 승인 / 취소 2종. 현재 pg_settlement_ledgers.transaction_type·pg_settlements.transaction_type 컬럼이 2종 기준으로 정의되어 있어 매핑 정책 결정 필요.

A안단순 압축
3종 취소 모두 → 취소
기존 컬럼 그대로 사용. 부분취소/기타취소 구분 사라짐 → 정산 차액 추적 불가능.
B안컬럼 확장
transaction_type enum을 4종으로 확장

C안 (추천)권장
기존 transaction_type 유지 + cancel_type 신설
transaction_type: 승인/취소 2종 유지 · cancel_type: FULL/PARTIAL/UNCLASSIFIED/NULL. 기존 로직 영향 최소, 상세 필요시만 cancel_type 참조.
📌 확인 포인트: UNCLASSIFIED_CANCEL은 포트원 수기 보정 fallback. 발생 시 슬랙 알림 + 운영팀 확인 프로세스 결정 필요.

02

fetch_status × reconciliation_status 병존 운영

두 컬럼은 의미가 달라 병존
컬럼의미값소스
pg_settlement_fetch_status 우리 시스템의 PG 정산 조회 진행 상태 (내부 운영 플래그) READY / COMPLETED / EXCLUDED 우리 자체 관리
reconciliation_status 신규 P0 포트원이 알려준 거래대사 결과 MATCHED / NOT_MATCHED / INCOMPARABLE / NOT_COLLECTED 포트원 API 응답

fetch_status 값 (확정)

READY대기

포트원 API 호출 전, 적재 대기 상태

COMPLETED완료

포트원 API 응답 + 적재 완료

EXCLUDED제외

당일 전체취소 등 정산내역 응답 누락 케이스

reconciliation_status 4종 — 발생 케이스 & 운영 프로세스 결정

MATCHED정상

PG ↔ 포트원의 거래금액·결제수단·승인일자 등 모든 필드 일치.

운영: 처리 없음 (자동 정산 진행)

NOT_MATCHED불일치

PG ↔ 포트원 거래정보 불일치. notMatchedReasons[]에 6종 사유 중 하나 이상.

운영: 포트원 문의 → 해결 후 재패치 / 슬랙 알림 노티

INCOMPARABLE미수집

PG엔 거래 있고 포트원엔 없음 (대사 불능). PG어드민 직접취소·PG/카드사 장애·수기결제 등.

운영: 포트원 결제 내역 웹훅·업데이트 후 재패치 / 슬랙 노티

NOT_COLLECTED조회불가

PG 정산만 있고 거래내역 미수집. 도입 초기 1회성 / 이후 지속 발생 시 포트원 CS 티켓 대상.

❓ 결정 필요: 단순 무시하고 MATCHED로 처리할지?
📌 당일 전체취소 (거래대사 API 한정) — 승인 row + 취소 row 양쪽 일치하므로 MATCHED. 단, 정산내역 API 응답에는 누락됨 (정산 대상 아님) → fetch_status = EXCLUDED로 표기.

결정 요약 — 오늘 확인할 것

⏳ 협의 대기 (개발실·경지실 확인)

  • actionType 매핑 — C안(transaction_type 유지 + cancel_type 신설) 확정 여부
  • 호출 주기 — 12:00 단일 vs 12:00+18:00 2회 패치
  • NOT_COLLECTED 운영 — 무시(MATCHED 처리) vs 별도 모니터링 큐
  • NOT_MATCHED / INCOMPARABLE 알림 채널 — 어느 슬랙 채널로 노티할지

✅ 결정 완료

  • 전체 PG 재백필 (NICE + 토스페이먼츠) — 포트원 채널키 이슈 개선 (~2026-06-03) 후 실행
  • fetch_status와 reconciliation_status 병존 운영 (의미 분리)
  • 신규 컬럼 5종 추가: reconciliation_status, not_matched_reasons, anomaly_amount, tax_free_amount, is_escrow
  • raw → 가공 흐름: pg_settlement_ledgers → pg_settlements
