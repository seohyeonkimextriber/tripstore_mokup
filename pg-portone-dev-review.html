SECTION 01

전체 작업 요약

포트원 V2 거래대사 API 연동을 위해 개발이 손대야 할 6개 영역

TASK 1
DB 컬럼 추가
`reconciliation_status`, `not_matched_reasons`, `anomaly_amount`, `tax_free_amount`, `is_escrow` — 5개 컬럼 신규 추가
TASK 2
ledgers 적재 로직
`pg_settlement_ledgers` (raw) — 포트원 응답 필드를 컬럼에 매핑하여 적재
TASK 3
settlements 가공 로직
`pg_settlements` (가공) — payment_code 단위로 집계/가공
TASK 4
reconciliation_status 운영
4종 상태값 처리 (MATCHED / NOT_MATCHED / NOT_COLLECTED / INCOMPARABLE) + 어드민 노출명 매핑
TASK 5
슬랙 알림 배치
일배치 1회 (전일자 → 익일 13:00). `#알림_결제오류확인` 채널로 코드블록 테이블 전송
TASK 6
데이터 백필 마이그레이션
2026-05-11 (토스페이먼츠 실결제 시작일) 이후 전체 거래 → 포트원 거래대사로 업데이트
📌 작업 성격
신규 작업 아님. 기존 NICEPAY 직연동을 포트원 V2 API로 갈아끼우는 마이그레이션. 정책·플로우는 기존 운영 기획서를 유지하고, 응답 스키마와 상태값 의미만 새로 매핑하는 것이 핵심입니다.

SECTION 05 · TASK 4

reconciliation_status 4종 운영

포트원이 알려주는 거래대사 결과 — 상태별 운영 액션과 어드민 노출명 (확정 2026-05-27)

신규 status 발생 케이스 운영 및 개발 프로세스 어드민 노출명
MATCHED 정상 승인 거래 — PG ↔ 포트원 거래금액·결제수단·승인일자 등 모든 필드 일치 알림 없음 (정상 처리) 정상
NOT_MATCHED PG ↔ 포트원 거래정보 불일치
notMatchedReasons 6종 중 하나 이상:
① PAYMENT_AMOUNT_NOT_MATCHED (금액)
② PAYMENT_DATE_NOT_MATCHED (일자)
③ VAT_AMOUNT_NOT_MATCHED (부가세)
④ TAX_FREE_AMOUNT_NOT_MATCHED (면세)
⑤ INSTALLMENT_MONTH_NOT_MATCHED (할부)
⑥ ESCROW_NOT_MATCHED (에스크로) 		슬랙 알림 ✅

• 인증: V2 API Secret을 Authorization 헤더에 담아 호출
• 엔드포인트: GET /payment-reconciliations (건별), 별도 API (거래일별·정산일별 합산 요약)

기존 NICEPAY 직연동과의 차이

개발 시 가장 큰 변경점 — 엔드포인트, 상태 enum, 호출 단위가 모두 바뀜

항목 기존 (NICEPAY 직연동) 신규 (포트원 V2)
API 엔드포인트 data.nicepay.co.kr/recon/api (sid 0301003) GET /payment-reconciliations
지원 PG NICE 단독 전체 (NICE / INICIS / KCP / KAKAOPAY / NAVERPAY ...)
호출 단위 MID 단위, 일자별 일괄 가맹점 전체, 페이지네이션 (커서)
건수 제한 실시간 10,000건/일 1회 최대 3개월 + 페이지네이션
조회 권장 시점 다음 영업일 08시 이후 전일자는 익일 12:00 이후
상태 enum 대기 / 완료 / 실패 / 제외 MATCHED / NOT_MATCHED / INCOMPARABLE / NOT_COLLECTED
불일치 검증 우리 자체 검증 포트원 사전 대사 + notMatchedReasons 6종
거래구분 0 (승인) / 2 (취소) APPROVAL / FULL_CANCEL / PARTIAL_CANCEL / UNCLASSIFIED_CANCEL / POST_CORRECTION
결제수단 코드 svcCd 01 / 03 CARD / EASY_PAY / VIRTUAL_ACCOUNT ... 9종
거래형태 (에스크로) 0 / 1 isEscrow boolean
